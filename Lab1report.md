#Report Lab 1

The aim of this project is to become familiar with Java classes through a practical implementation. Specifically, this project  required implementing the Record and Vector classes, as well as a TestRecord class to ensure the classes worked correctly. It is also important to highlight the classes' relationships. In this project we can see clearly that Vector and Record have interacted directly. The Record class has a Vector, forming a relationship of composition. In general, this lab is a bridge between theoretical understanding and practical implementation.

Each class had the following objectives. The record class was the simplest, it stores a Vector as an input, and a double as the output. It also includes a method to convert its information into a string. The vector class was a bit more complex. It stores an array of doubles as an attribute and includes multiple methods: two constructors, one that initializes the vector from an existing array, and another that creates a vector of a given size with all elements set to a specified value. Clearly, it also has getters, and methods to perform vector addition, compute the dot product, calculate the norm, and convert the vector into a string for printing.

During the development of this project, several solutions were considered. For instance, at the beginning, I thought of the idea of implementing two vector classes, one specifically for the Record class. After creating everything, I realized I could just use the Vector class and didn’t need the auxiliar class. Now, after finishing I knoe it was just a way of making the code less efficient. This is just one of the many ways to see and approach this project. 

I will now explain each class and the difficulties and challenges encountered. As mentioned before, the Record class was relatively easy to implement, the main complication came from the auxiliar Vector class I had to create, which was later removed. Then I created the TestRecord for this class, and I doubted whether the values should be obtained by an external user or simply predefined. Since this is my first time programming in Java, I researched how scanning users' inputs worked and started implementing it. After discussing it with some classmates, it was clear that it would work just fine with predetermined inputs. To prove the correct functionality, I first only printed the values of the record class, but then I realized it could be better by adding a boolean variable that verifies that the stored values matched the inputs, ensuring that the functions worked correctly. Then, I considered this part as finished.

The second part, the Vector class, had its difficulties as well. I believe the toughest part was just how prolonged this was, the methods on their own didn't have much difficulty. This class also had different approaches. The thought of using an ArrayList instead of an array to have more flexibility crossed my mind, but I thought I would just be making things more complex, so it didn’t take me much time to reject this idea. I also thought of whether the vector had to be doubles or integers. Finally, I believed doubles would be more accurate and precise when doing operations, specifically norms and roots. Then, I had to do the proofs that everything works correctly, and I followed the same method as for the Record class. 

After coding this project, everything came together, and all tests passed. I believe that both classes showed a clear example of encapsulation: Vector hides the array of doubles, Record hides how data is stored, for instance. And relatedly, abstraction: you don’t need to know how the vector stores numbers, only what operations it performs. I believe that this project not only helped me familiarize myself with this language, but it also allowed me to gain an understanding of classes and their interactions. My biggest challenge was definitely seeing the end of this project, because sometimes I felt as if my knowledge wasn’t sufficient and that I would be able to finish it, but, with patience, even though I don't have much, I was able to complete it. I also think that at the beginning, I focused more on getting the work done rather than on thinking of how things had to work together, which negatively impacted my work at the beginning. Even though I'm satisfied with the outcome, it is clear that this project has many limitations, we could have included the user's input or even a dimension validation. So, I would say that the most important thing I got from this project is the first practical contact with classes and their relation.
